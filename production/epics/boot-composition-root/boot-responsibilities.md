> **Consumer**: `/create-control-manifest update` (technical-director, separate approval) lifts the two tables' rows into Foundation → Required Patterns ("Boot responsibilities") and Forbidden Approaches. This file changes no code.

**Why the list exists.** TD-001 was a `GameManager` autoload god object that owned rules, mana, combat and run state; TD-009 was untyped global run state reached through a singleton (architecture.md §Tech-debt retirement mapping). Both regrow one convenient line at a time inside the one autoload a project is allowed. Every row below names the TD item it guards; a `Boot` change that adds a responsibility not listed here is an architecture change (ADR-0001: a second autoload or a new duty is a new ADR), not a refactor.

Tags: **MVP** — in the code today, pointing at the member and the test that proves it. **later (<epic>)** — decided by an ADR, lands with that epic; the code carries a `TODO(<epic>)` or comment at the spot.

## Observations for the manifest revision (not rows)

- architecture.md §Data Flow 5 step 2 names the `ai_profile` validator `BossAI.validate_profile_key`; the code registers `BossAI.validate_ai_profile` (boss-ai, 2026-11-04 code review). The manifest row should cite the code's name; architecture.md wants the same one-word fix at its next revision.
- architecture.md's "Boot does" first row says `boot()` constructs `ProfileStore` and calls `load_profile()`. That is the post-switch shape; at MVP `MetaStub` stands in (ADR-0011 D4) and `Services.profile_store` is `null`, typed `RefCounted` until `ProfileStore` exists (`TODO(meta-progression)` in `services.gd`).
- Proposed Foundation rows for `/create-control-manifest update` (wording for the technical-director to accept or edit):
  - **Required**: "**`Boot` responsibilities are exactly the 'Boot does' rows of `production/epics/boot-composition-root/boot-responsibilities.md`** — MVP: lazy `boot(overrides)` (idempotent; steps 2–4: `CardDatabase.load(_collect_validators())`, `MetaStub` or the `meta` override, the Meta implementation's `settings_bus`), `services()` to scene roots and debug loaders, a read-only `booted`; later, with their epics: Meta's heartbeat/debounce `Timer`s and `release_lock()` exit hook started in `boot()`, the `MetaFacade` one-line switch, debug-loader override keys, `bindings` → `InputMap` (Alpha). A new duty is an ADR change — source: ADR-0001 D4, ADR-0004 D6/D8/addendum, ADR-0011 D4 (TD-001, TD-009)".
  - **Forbidden**: "**Never give `Boot` game state, a rules tick, a `load()` in `_ready()`, a per-service getter, a sibling autoload or a second composition path** — the 'Boot never does' rows; `test_boot_holds_no_game_state_fields` pins its fields — source: ADR-0001 D4 (TD-001, TD-009)". The existing service-locator, second-autoload, second-composition-path, G3 and accept-all rows stay.
