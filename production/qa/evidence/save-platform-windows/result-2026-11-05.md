# Atomic write on Windows (epic gate condition 9; ADR-0004 Engine Compatibility)

**Date:** 2026-11-05. **OS:** Windows 11 Home 10.0.26100. **Engine:** Godot 4.7.2 stable,
editor console binary, headless.
**Suites:** `tests/integration/save/atomic_write_platform_test.gd` (10 cases),
`tests/integration/save/atomic_write_test.gd` (11 cases). All passed.

**Limit:** ADR-0004 asks for the run "on the exported build". This run is the editor binary.
No export template is installed (TD-013 records the same gap), so the exported build is not
measured. `FileAccess` and `DirAccess` are the same engine code, but that is an inference,
not an observation.

## Observed

| Question | Result |
|---|---|
| Rename over an existing `.bak` (W7) | `OK`, first attempt, no fallback (`test_bak_rotation_over_existing_bak`) |
| Rename `.tmp` to a final path that is absent (W8) | `OK` |
| Rename `.tmp` over an existing file, no backup (lock, run records, `RECOVERED_BAK`) | `OK` |
| 50 consecutive writes | `.bak` always the previous generation, no `.tmp` left |
| Reader open on `.bak` across a write (indexer shape) | W7 fails, `E_IO`; `profile.json` unchanged, no `.tmp`; the write after the reader closes succeeds |
| Reader open on `profile.json` across a write | W7 fails, `E_IO`; `profile.json` unchanged, no `.tmp`; the write after the reader closes succeeds |

## What the open-file rows mean

On Windows a held file makes the save fail rather than corrupt anything: the player sees
`E_IO` handling, and the next mutator retries. When the reader is on `profile.json`, W7's
fallback deletes the old `.bak` before it retries, so a failed save there can cost the
backup. ADR-0004 accepts that ("losing the backup-of-the-backup, never the profile"), but
the backup lost here is the good one, deleted for a lock it did not hold. `profile.json` is
intact in that state, and the next successful write makes a new `.bak`.

Not run: the process-kill test `tools/qa/save_kill_test.sh` (ADR-0004 Verification), which
does not exist in the repo and is specified for Linux CI.
